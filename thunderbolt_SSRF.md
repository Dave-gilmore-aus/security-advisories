# Security Advisory: Server-Side Request Forgery (SSRF) via Link Preview Endpoint in Thunderbolt
 
**Author:** Dave-gilmore-aus  
**Software:** Thunderbolt  
**Affected Versions:** 1.0.0  
**Fixed Version:** Unpatched / None  
**Status:** Unresponsive Maintainer (30+ days since private disclosure)

---

## Executive Summary

The `/link-preview/` endpoint in Thunderbolt is vulnerable to Server-Side Request Forgery (SSRF). The application processes arbitrary, user-supplied URLs and attempts to fetch metadata from them. Because the application lacks strict input validation or destination allowlists, a remote attacker can abuse this feature to coerce the server into making unauthorized HTTP requests to internal network infrastructure or restricted external services.

## Vulnerability Details

- **Vulnerability Type:** Server-Side Request Forgery (SSRF) (CWE-918)
- **Component/File:** `/link-preview/[target_url]` Route & Backend Scraper Logic
- **Impact:** High — Allows internal network scanning and unauthorized access to local/cloud metadata infrastructure.

### Technical Description

The application exposes a route at `/link-preview/[target_url]` designed to generate link summaries by parsing target metadata. However, by interacting directly with the API and passing URL-encoded strings, an attacker can bypass frontend controls.

The backend scraper attempts to resolve and connect to any arbitrary URI provided, including internal loopback addresses (`127.0.0.1`, `localhost`) and private subnets. When an internal connection attempt fails, the backend bubbles up a distinct `NOT_FOUND` string. This behavioral difference confirms that the user-supplied input successfully reached the backend’s network-fetching logic, enabling blind or semi-blind SSRF.

## Proof of Concept (PoC)

> ⚠️ **Disclaimer:** This PoC is intended exclusively for educational and defensive security validation.

To reproduce the SSRF vulnerability:

1. Open a terminal and issue a direct API request targeting the server's own loopback address:

```bash
curl -i http://localhost:8000/link-preview/http%3A%2F%2F127.0.0.1%3A8000%2Fv1%2Fhealth
```

### Observed Result

The HTTP response body returns a custom `NOT_FOUND` string generated by the application's internal scraping engine, proving the server processed the loopback request.

### Log Verification

Monitor the backend server stdout logs to observe the server actively attempting to resolve and establish a network connection to the internal address.

## Impact

An attacker can weaponize this SSRF vulnerability to achieve the following:

- **Internal Port Scanning:** Map services running on the server's localhost or internal network that are shielded from the public internet.
- **Firewall & ACL Circumvention:** Use the trusted backend server as a proxy to query restricted cloud metadata endpoints (e.g., AWS IMDSv1/v2 at `169.254.169.254` or GCP metadata services) to potentially harvest IAM credentials and tokens.
- **Information Disclosure:** Enumerate local API structures and potentially leak software versions or private data exposed on internal networks.
